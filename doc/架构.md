## 一、形态与依赖

Rust 库（`lib` 名 `asign_sdk`，包名 `asign-sdk`），edition 2021，实现对爱签 OpenAPI V3.0 的封装。

| 依赖 | 用途 |
| --- | --- |
| `reqwest`（`json` + `rustls-tls` + `multipart`） | HTTP 与 form-data 上传 |
| `rsa`（`sha1` + `sha2`） | 签名 |
| `serde` / `serde_json` | 报文与 JSON key 排序 |
| `chrono` | 时间字段 |
| `tokio`（仅 dev-dependencies） | 测试运行时 |

## 二、模块划分

| 文件 | 职责 |
| --- | --- |
| `src/lib.rs` | crate 根与重导出 |
| `src/client.rs` | `AsignClient`（发请求、装配 form-data、解包响应）与 `ApiEnvelope`（爱签统一响应外壳） |
| `src/config.rs` | `AsignConfig`、`Environment`（含 `base_url()`） |
| `src/sign.rs` | 签名原语：`SignerKey`、`compute_sign`、`md5_hex`、`sort_json_keys` |
| `src/error.rs` | `AsignError` 与 `AsignResult` |
| `src/api/mod.rs` | 接口模块的汇总导出 |
| `src/api/*.rs` | 按业务域拆分的接口，共 41 个 `pub async fn` |

`src/api/` 各域与接口数：

| 模块 | 接口数 | 业务域 |
| --- | --- | --- |
| `user.rs` | 14 | 用户同步、查询、修改 |
| `seal.rs` | 9 | 印章/印模管理 |
| `sign_task.rs` | 7 | 签署任务与签署链接 |
| `auth.rs` | 7 | 实名认证与认证流水号 |
| `app.rs` | 1 | 应用管理 |
| `file.rs` | 1 | 文件上传 |
| `template.rs` | 1 | 模板 |
| `evidence.rs` | 1 | 存证 |

## 三、公开导出面

`lib.rs` 对外暴露 `pub mod api`，以及：

- `AsignClient`、`ApiEnvelope`
- `AsignConfig`、`Environment`
- `AsignError`、`AsignResult`
- `SignerKey`、`compute_sign`、`md5_hex`、`sort_json_keys`

## 四、调用链

```text
src/api/*.rs 的域方法
  └─ AsignClient 发请求
       ├─ sort_json_keys + compute_sign（SHA1withRSA，走 sign.rs）
       ├─ form-data 封装（业务参数 + 签名 + appId）
       └─ 解 ApiEnvelope → AsignResult<T>
```

域方法只负责组装参数；签名、报文封装与响应解包都收在 `client.rs` 与 `sign.rs`，这也是排查签名类错误时只看这两个文件就够的原因。

## 五、与后端的关系

`backend_73info` 以 path 依赖消费本 SDK，后端侧的消费方是 `contract`（签署任务）、`asign_seal`（印章）、`asign_user`（用户同步与实名）三个模块。后端配置结构是 `AsignSettings`（`src/settings.rs`），字段包括 `environment`、`app_id`、`private_key_path`、回调与前端地址，以及三方合同丙方的企业账号与印章编号（`platform_*`）。详见 [backend_73info/doc/配置与密钥.md](../../backend_73info/doc/配置与密钥.md) 第三节。

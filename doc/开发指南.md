# asign-sdk 开发指南

> **覆盖**：构建与测试、示例脚本的用途与运行方式、密钥边界、新增接口的改法。
> **不覆盖**：模块划分与调用链 → [架构.md](架构.md)；爱签协议细节 → 爱签官方接口文档。

## 一、命令

```bash
cargo check
cargo test                       # tests/sign_test.rs，3 个签名用例
cargo run --example smoke        # 最小示例
```

`tests/sign_test.rs` 只测签名原语，不联网、不需要凭据。其余验证靠 `examples/` 下的脚本。

## 二、示例脚本

示例都从环境变量读凭据，不写死 appId 与密钥路径：

| 变量 | 用途 |
| --- | --- |
| `ASIGN_APP_ID` | 应用 AppId（缺省 `your-app-id`，此时请求会被渠道拒绝） |
| `ASIGN_PRIVATE_KEY_PATH` | RSA 私钥（PKCS#8 PEM）文件路径，缺省 `keys/asign_private_key.pem` |

| 示例 | 用途 | 参数 |
| --- | --- | --- |
| `examples/smoke.rs` | 最小示例：创建客户端并查一次用户信息 | 无 |
| `examples/check_status.rs` | 打印 `contract/status` 与 `contract/getContract` 的原始返回结构 | `<contractNo>` |
| `examples/preview_seal.rs` | 调 `previewContract` 看签章与时间戳的落位 | `<contractNo> <account>` |

几点须知：

- 这些示例会真实调用爱签接口。运行前确认当前环境与账号。
- `preview_seal.rs` 里的 `signKey` 锚点必须与你的合同模板**逐字一致**，漂移了会报 `100091 关键字未找到`。

## 三、密钥与忽略规则

- `/keys/` 被 `.gitignore` 忽略，用于放本地私钥；**不要把私钥放进仓库**。
- `Cargo.lock` 也被忽略（库的常规做法）。
- 生产与测试用不同的 appId/密钥，`Environment` 决定 `base_url()`。

## 四、新增一个接口

1. 判断业务域，放进 `src/api/` 下对应的模块；没有合适的域就在 `api/mod.rs` 里新增并导出。
2. 域方法只组装业务参数，签名与 form-data 封装交给 `AsignClient`，不要在域方法里重复实现。
3. 返回值统一 `AsignResult<T>`；爱签的统一响应外壳由 `ApiEnvelope` 解包。
4. 纯逻辑（key 排序、签署串拼接）适合加进 `tests/sign_test.rs`。
5. 需要现场验证结构时就加一个 `examples/` 脚本，把用法写在头部 `//!` 注释里。

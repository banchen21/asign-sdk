# asign-sdk 开发指南

> **覆盖**：构建与测试、示例脚本的用途与运行方式、密钥边界、新增接口的改法。
> **不覆盖**：模块划分与调用链 → [架构.md](架构.md)；爱签协议细节 → 技能 `asign`。
> 上级约定：[AGENTS.md](../../AGENTS.md)

## 一、命令

```bash
cargo check
cargo test                       # tests/sign_test.rs，3 个签名用例
cargo run --example smoke        # 最小联调示例
```

`tests/sign_test.rs` 只测签名原语，不联网、不需要凭据。其余验证靠 `examples/` 下的一次性脚本。

## 二、示例脚本

| 示例 | 用途 | 参数 |
| --- | --- | --- |
| `examples/smoke.rs` | 最小联调：用真实 appId + 私钥创建客户端并查一次用户信息 | 无 |
| `examples/check_status.rs` | 诊断：打印 `contract/status` 与 `contract/getContract` 的原始返回结构 | `<contractNo>` |
| `examples/reproduce_prod.rs` | 复现线上错误：用生产配置（密钥 + production + app_id）直接调爱签 | 无 |
| `examples/preview_seal.rs` | 诊断落位：以指定账号调 `previewContract` 看签章与时间戳落在哪一行 | `<contractNo> <account> [private_key_path]` |
| `examples/probe_preview.rs` | 探针：用空的 `signStrategyList` 调 `previewContract`，确认是否还画落位标记 | `<contractNo> <account>` |

几点须知：

- **密钥来源与完整参数说明写在每个文件头部的 `//!` 注释里**，跑之前先读它。
- `preview_seal.rs` 存在的原因见它自己的注释：用户端预览接口只允许合同当事人调用，平台账号不是可登录用户，所以「平台公章落在哪一行」没法走后端接口看，只能在 SDK 侧直调。它里面的锚点必须与后端 `src/modules/contract/service.rs` 的 `sign_anchors()` / `sign_date_anchor()` **逐字一致**，漂移了会报 `100091 关键字未找到`。
- `preview_seal.rs` 与 `probe_preview.rs` 目前**未被 git 跟踪**（诊断工具性质，是否入库自行判断）。
- 这些示例会真实调用爱签接口，`reproduce_prod.rs` 更是直接打生产。运行前确认当前环境与账号。

## 三、密钥与忽略规则

- `/keys/` 被 `.gitignore` 忽略，用于放本地私钥；**不要把私钥放进仓库**。
- `Cargo.lock` 也被忽略（库的常规做法，与应用的做法不同——`adapay-sdk` 是把 `Cargo.lock` 入库的）。
- 生产与测试用不同的 appId/密钥，`Environment` 决定 `base_url()`。

## 四、新增一个接口

1. 判断业务域，放进 `src/api/` 下对应的模块；没有合适的域就在 `api/mod.rs` 里新增并导出。
2. 域方法只组装业务参数，签名与 form-data 封装交给 `AsignClient`，不要在域方法里重复实现。
3. 返回值统一 `AsignResult<T>`；爱签的统一响应外壳由 `ApiEnvelope` 解包。
4. 纯逻辑（key 排序、签署串拼接）适合加进 `tests/sign_test.rs`。
5. 需要现场验证结构时就加一个 `examples/` 脚本，把用法写在头部 `//!` 注释里——这也是现有 5 个示例的来历。
